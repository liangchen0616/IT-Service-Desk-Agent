# 工具调用基础

tools/executor.py 定义只读工具接口、注册表、参数检查、执行期限和统一结果。tools/knowledge_search.py 将现有检索器包装为 knowledge_search。API、完整 Agent CLI 和 Agent benchmark 通过现有 retrieve 节点使用它。

当前是工作流控制的工具调用：每轮先检索，资料不足时最多重写两次后再次检索，总共最多三次。不是模型自由选择工具的通用代理，另有显式开启的公开搜索工具（见 web_search.md），没有任意代码执行或文档删除工具。文档删除仍由用户显式调用管理接口。

参数 query 必须是非空字符串且不超过 1000 字符；top_k 必须是正整数，不能超过当前检索配置。多余字段和类型转换被拒绝。工具执行器只接受明确注册且声明只读的工具，禁止重名。只读声明是开发接口约定，不是操作系统权限隔离。

统一结果包含 name、call_number、status、elapsed_ms、data、error_code。失败类型包括 unknown_tool、invalid_arguments、call_limit、timeout、model_error、execution_failed。失败结果不带部分证据，不自动重试；检索节点清空本次证据并进入错误回退，避免把执行失败误当成正常的资料不足。模型错误仍映射 API 503，其他工具故障为工作流错误 500。

调用次数由每次 Agent 请求自己的状态维护，执行器检查传入序号不超过三次；不使用跨请求全局计数。工具描述提供 JSON Schema，供后续受控的工具选择机制使用。

AGENT_TOOL_TIMEOUT 默认 180 秒，表示每次工具执行的协作式期限。执行前后检查时钟，超过期限的结果会丢弃。当前同步本地向量计算无法被安全强制中断，因此不能保证 API 在该秒数内返回；没有遗留后台线程。后续联网工具应使用 context.remaining_seconds() 设置实际网络超时。

API trace 的 retrieve 条目新增 tool，记录名称、调用序号、状态、耗时和错误码；不记录问题或片段正文。应用日志增加对应工具字段，不输出底层异常消息。证据对象保留原文、来源、PDF 页码与文档编号，继续经过资料判断和引用校验。

公开搜索使用独立的一次调用额度，本地搜索仍最多三次。其实际网络超时受剩余工具期限约束，错误继续沿用统一工具结果。
